🚀 راهنمای سریع و خط‌مشی پروژه Telegram-Chat

مرجع گام‌به‌گام برای توسعه بدون ریسک، دیپلوی ایمن و بازگردانی سریع هنگام بروز مشکل

⚡ دستورات سریع ترمینال (یک کلیک تا اجرا) Package Scripts

این دستورات در فایل package.json تعریف شده‌اند و تمام کارهای پیچیده را به صورت خودکار انجام می‌دهند:

۱. استقرار نهایی روی نسخه اصلی (با بکاپ‌گیری خودکار دیتابیس):

این دستور ابتدا یک فایل بکاپ کامل از دیتابیس فعلی در پوشه backups می‌گیرد، سپس کدها را به سرور اصلی کلودفلر می‌فرستد.

npm run deploy:prod
۲. استقرار در محیط آزمایشی (بدون کوچک‌ترین ریسک برای نسخه اصلی):

کدها فقط روی ساب‌دامین و دیتابیس آزمایشی مستقر می‌شوند و کاربران اصلی متوجه هیچ تغییری نخواهند شد.

npm run deploy:staging
۳. بازگشت آنی به نسخه قبل در صورت خرابی (Workers Rollback):

اگر کدی دیپلوی شد و کار نکرد، این دستور در کمتر از ۱ ثانیه سرور کلودفلر را به آخرین نسخه پایدار قبلی برمی‌گرداند.

npm run rollback:prod
۴. گرفتن بکاپ لحظه‌ای دستی از دیتابیس D1:
npm run backup:prod
🔄 فرآیند امن توسعه با GitHub Desktop گام‌به‌گام تصویری
۱
شاخه آزمایشی بسازید (New Branch)

در بالای GitHub Desktop روی Current Branch کلیک کنید، دکمه New Branch را بزنید و نامی مثل feature/notification-fix انتخاب کنید. شاخه اصلی (main) دست‌نخورده باقی می‌ماند.

۲
تغییرات را در محیط آزمایشی تست کنید

کدها را ویرایش کرده و دستور npm run deploy:staging را بزنید. لینک آزمایشی را در مرورگر باز کنید و همه چیز (ارسال پیام، نوتیفیکیشن و...) را بررسی کنید.

۳
در صورت شکست: شاخه را حذف کنید (Discard & Delete)

اگر آزمایش‌ها خوب پیش نرفت، به شاخه اصلی سوییچ کنید و شاخه آزمایشی را پاک کنید. هیچ باگی به سرور و دیتابیس اصلی شما سرایت نکرده است.

۴
در صورت موفقیت: ادغام با شاخه اصلی (Merge to Main)

در GitHub Desktop به شاخه main برگردید. از منوی بالا روی Branch و سپس Merge into current branch... بزنید و شاخه آزمایشی را انتخاب کنید. در نهایت دستور npm run deploy:prod را در ترمینال اجرا کنید.

🚨 جعبه کمک‌های اولیه (بازگردانی اضطراری) Rollback Guide

اگر مشکلی پیش آمد، بسته به این که مشکل کجاست از راه‌حل مربوطه استفاده کنید:

الف) کدها خراب شده ولی هنوز دیپلوی نکرده‌اید:
در GitHub Desktop در ستون چپ (Changes)، روی فایل‌ها راست‌کلیک کرده و Discard all changes را بزنید تا همه‌چیز فوراً به حالت اول برگردد.
ب) کد به سرور ارسال شده و سایت اصلی بالا نمی‌آید:
بلافاصله در ترمینال دستور npm run rollback:prod را بزنید تا کلودفلر در ۱ ثانیه به نسخه قبلی برگردد.
ج) دیتابیس خراب شده یا داده‌ها نامعتبر شده‌اند:
فایل بکاپی که در پوشه backups وجود دارد را با دستور زیر بازگردانی کنید:
npx wrangler d1 execute chat-db --remote --file=./backups/latest-backup.sql
