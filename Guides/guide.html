🚀 راهنمای سریع و خط‌مشی پروژه Telegram-Chat

دستورات آماده با پیشوند NPX سازگار با تمام نسخه‌های ویندوز و CMD

⚡ دستورات مستقیم ترمینال (آماده کپی و اجرا با NPX) بدون نیاز به نصب جهانی

تمامی دستورات زیر مستقیماً با پیشوند npx تنظیم شده‌اند تا با کلیک روی «کپی دستور» و پیست در ترمینال، بدون مواجهه با ارور is not recognized اجرا شوند:

۱. استقرار نهایی روی نسخه اصلی (با بکاپ‌گیری خودکار دیتابیس D1):

ابتدا یک نسخه پشتیبان از دیتابیس در پوشه backups می‌گیرد و سپس برنامه را دیپلوی می‌کند.

npx wrangler d1 export chat-db --remote --output=./backups/latest-backup.sql && npx wrangler deploy
۲. استقرار در محیط آزمایشی (Staging - بدون دست‌زدن به نسخه اصلی):

برنامه را منحصراً روی ساب‌دامین استیجینگ و دیتابیس آزمایشی chat-db-staging مستقر می‌کند.

npx wrangler deploy --env staging
۳. بازگشت آنی به نسخه سالم قبلی در صورت بروز باگ (Workers Rollback):

اگر کد جدید کار نکرد، در ۱ ثانیه سرور کلودفلر را به آخرین نسخه پایدار برمی‌گرداند.

npx wrangler rollback
۴. گرفتن بکاپ دستی از دیتابیس اصلی D1:

فایل بکاپ را داخل پوشه backups/latest-backup.sql ذخیره می‌کند.

npx wrangler d1 export chat-db --remote --output=./backups/latest-backup.sql
🔄 فرآیند مرحله به مرحله در GitHub Desktop محیط گرافیکی
۱
ایجاد شاخه جدید (New Branch)

در بالای GitHub Desktop روی Current Branch کلیک کرده و دکمه New Branch را بزنید. نامی مانند feature/new-feature انتخاب کنید تا نسخه اصلی (main) امن بماند.

۲
تست در محیط Staging

کدها را تغییر دهید و دستور شماره ۲ (npx wrangler deploy --env staging) را اجرا کنید. در آدرس استیجینگ همه چیز را تست کنید.

۳
اگر آزمایش شکست خورد (پاک‌سازی بدون ریسک):

در GitHub Desktop به شاخه main بازگردید و شاخه آزمایشی را حذف (Delete) کنید. سایت و دیتابیس اصلی شما دست‌نخورده باقی می‌ماند.

۴
اگر موفق بود: ارتقا به نسخه اصلی (Merge & Deploy)

در GitHub Desktop به شاخه main بروید. از منوی بالا گزینه Branch > Merge into current branch... را انتخاب کرده و شاخه آزمایشی را ادغام کنید. سپس دستور شماره ۱ را در ترمینال بزنید.

🚨 جعبه کمک‌های اولیه (وقتی همه‌چیز خراب شد) Rollback Tools
الف) کدها روی سیستم شما بهم ریخته ولی هنوز Commit نکرده‌اید:
در GitHub Desktop در ستون سمت چپ (تب Changes)، روی فایل‌ها راست‌کلیک کرده و گزینه Discard all changes را بزنید تا فایل‌ها به حالت اول برگردند.
ب) سایت اصلی پس از دیپلوی بالا نمی‌آید:
دستور شماره ۳ (npx wrangler rollback) را در ترمینال بزنید تا کلودفلر فوراً به نسخه قبلی سوئیچ کند.
ج) دیتابیس پاک شده یا داده‌ها نامعتبر شده‌اند:
با دستور زیر آخرین فایل بکاپ را به دیتابیس برگردانید:
npx wrangler d1 execute chat-db --remote --file=./backups/latest-backup.sql
